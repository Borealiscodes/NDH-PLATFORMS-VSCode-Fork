---

## **🌱 1. Purpose of This Roadmap**

This roadmap provides a **clear build sequence** and **navigation structure** for the NDH‑PLATFORMS‑VSCode‑Fork experimental platform.  
It does **not** define canonical NDH architecture.  
It does **not** prescribe outcomes.  
It simply orients contributors through the platform’s evolution.

The authoritative architecture lives in:

- **Platform Blueprint Suite**  
- **CONTRIBUTING.md**  
- **Holonomy Behavior Guide (pending)**  
- **White Paper Staging README (pending)**  

This roadmap references those artifacts and defines the order in which the platform should grow.

---

## **🧭 2. High‑Level Roadmap Summary**

The NDH experimental platform evolves in **ten phases**, each building on the previous one:

1. **Blueprint Suite**  
2. **Contributor Governance**  
3. **Holonomy Guide**  
4. **White Paper Staging Surface**  
5. **Snek Onboarding**  
6. **NDH Extension Templates**  
7. **GBS Transformation Maps**  
8. **Trauma‑Informed UX Prototypes**  
9. **NDH Primitive Prototypes**  
10. **Expressive Manifold Expansion**

This sequence preserves holonomy, prevents domain absorption, and maintains NDH architectural clarity.

## **📐 4. Holonomy Checkpoints**

At each phase, contributors must verify:

- **Coherence** (no drift)  
- **Boundary integrity** (no domain absorption)  
- **Non‑dual alignment**  
- **Trauma‑informed UX compliance**  
- **Expressive clarity**  
- **Canonical NDH protection**

These checkpoints ensure the platform remains stable as it evolves.

---

## **📦 5. Migration Rules**

Only **stable**, **reviewed**, **holonomy‑aligned** artifacts may migrate to NDH‑PLATFORMS canonical.

Migration requires:

- holonomy notes  
- GBS transformation summary  
- UX dignity constraints  
- expressive context (if relevant)  
- architectural justification  

Nothing migrates automatically.
